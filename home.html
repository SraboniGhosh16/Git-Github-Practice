Notes on Git & Github

Configure Git

  • git config --global user.name "Your Name"
  • git config --global user.email "you@example.com"

Basic Commands

  • git --version (to check the version installed)
  • cd .\filepath (to go inside a file/folder)
  • cd .. (to come out of a file/folder)
  • ls (shows the list of files)
  • ls -hidden (shows the list of hidden files. every GitHub repository has a .git file as hidden file, any repository without it is not a GitHub repository but a local repository.)
  • git log (shows all the commits with messages)
  • git rm filename (removes/deletes the file)
  • git rm -r foldername (removes/deletes the folder)
  • git mv name newname (renames a file)
  • git mv file folder/file (moves file into folder)

Git Clone

  • git clone link (to clone the remote repository in local space. the link is from GitHub repository - <> Code - local - HTTPS)

Git Init

  • mkdir foldername (to make a local repository or folder)
  • git init (to make the local repository a GitHub repository, but still not reflected on GitHub)
  • git remote add origin repositorylink (to connect the local repository the GitHub repository that's link is given, now reflected on GitHub)
  • git remote -v (to verify if local is successfully connected to remote. gives the GitHub repo link)

Stage, Commit, Push & Pull

  • git status to check if everything is upto date or anything is under :
    • Untracked files - new file created and not added
    • Changes not staged for commit - changes made inside a file but not added
    • Changes to be committed - changes are added or staged but not committed
    • Your branch is ahead of 'origin/main' - changes are committed with message but not pushed to repository
  • git add filename (adding/staging any changes made inside a file or any new file created)
  • git add . (adding/staging all the changes)
  • git commit -m "message" (committing the changes with a message)
  • git push origin main (uploading local repo content to remote repo)
  • git pull origin main (to fetch and download content from remote repo and immediately update the local repo to match that content)

Git Branch

  • git branch (shows the branches and the current branch that we are on is colored green)
  • git checkout -b branchname (creates a new branch)
  • git checkout branchname (takes to the branch that's name is given)
  • git branch -M branchname (renames the branch)
  • git branch -d branchname (deletes the branch with that name, but we have to be on the main branch to delete)

  • Few basic steps on branches:
    • to make changes on a branch, we have to be on that branch (*git checkout branchname* takes us to that branch).
    • after making the changes we do "git add ./git add filename" to stage the changes and "git commit -m message" to commit the changes.
    • now instead of doing "git push/ git push origin main", to push the changes only on a branch we have to write git push origin branchname.
    • now a new branch with all the changes will be reflected on GitHub

  • git diff main (shows the differences between 2 branches: main and the branch that we are on. we can see difference between any 2 branches. we can any branch name on the command and compare it with the current branch)
  • git merge branchname (to merge the branches (current branch and the branch name that is given in the command), this is done on VSCode command line)

  • PULL REQUEST
    • PR is done on GitHub website. on GitHub we do a pull request, so that the merge can be compared and then accepted to be merged.
    • Compare & pull request -> Add message and description for the request -> Create pull request -> GitHub checks if it can be automatically changed or not, checks for conflicts -> Merge pull request -> Confirm merge -> successful
    • After doing successful merge on GitHub we have to do git pull origin main command to reflect the changes on local repo.
    • now a new branch with all the changes will be reflected on GitHub

  • Resolving Merge Conflicts
    • after merging some conflicts can occur. this conflicts can be handled using Merge Conflicts.
    • Accept Current Change - change made on current branch.
    • Accept Incoming Change - change made on the another branch.
    • Accept Both Changes - both changes.

Undoing the Staged Changes

  • git reset filename (undoing the changes made on the file which were staged/added earlier with "git add ." command)
  • git reset (undoing all the changes that were made which were staged/added earlier with "git add ."" command)
  • "git reset/git reset filename" basically undos the staging/adding part, nothing is removed from the code itself, only the staging is removed.

Undoing the Committed Changes

  • git reset HEAD~1 (undos the last commit made)
  • git reset commithash (undos the commit and takes the head to that commit whose commit hash is given, that becomes the latest commit and the other commits that were made after it, becomes not committed. commit hash is copied from the log.)
  • git reset --hard commithash (undos commits and also refllects that)
